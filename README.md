# EcoWeaver AI

EcoWeaver AI is an urban ecological planning platform for understanding how changes to a tree network can affect habitat connectivity. It combines an interactive map, species and corridor data, graph-based simulation, and a report-oriented interface around a Cubbon Park, Bengaluru demonstration dataset.

The central question is simple: **what changes when a development decision removes one part of an ecological network?** EcoWeaver makes that question visible before a decision becomes permanent.

> This repository is an MVP and demonstration system. Its Cubbon Park data is synthetic, and its connectivity model is a simplified planning aid rather than a validated ecological assessment.

## What You Can Explore

- **Eco Map** (`/map`): Browse the monitored tree inventory, inspect individual trees, and view ecological value and network context.
- **Species** (`/species`): Explore the species catalogue and ecological relationships represented in the demo.
- **Habitat Simulator** (`/simulator`): Run tree-removal, planting, and canopy-bridge scenarios and compare network metrics before and after an action.
- **Canopy Guardian** (`/canopy-guardian`): Review canopy, corridor, and keystone-node indicators.
- **Bioacoustic AI** (`/bioacoustics`): Audio analysis of urban birds and nocturnal fauna with real-time Arduino sensor telemetry.
- **Impact Reports** (`/reports`): Review the report-style summary and mitigation guidance generated by the current demo experience.
- **About** (`/about`): Read the project's mission, scope, and roadmap.

The fastest guided path is the Cubbon Park preset:

```text
/simulator?demo=cubbon-park
```

## Demo Dataset

The application ships with a Cubbon Park dataset containing a detailed tree inventory, species records, zones, and wildlife corridors. Tree `#021` is used as the featured critical-node scenario in the simulator. The interface uses this dataset to demonstrate how a single removal can alter connectivity, canopy area, corridor status, and affected fauna.

Treat every number in the demo as illustrative. Production use would require field surveys, authoritative GIS layers, species-specific movement data, and validation by qualified ecologists.

## Architecture

EcoWeaver is a Next.js App Router application written in TypeScript.

| Layer | Implementation |
| --- | --- |
| Web application | Next.js 16, React 19, TypeScript |
| Styling and motion | Tailwind CSS 4, Framer Motion, custom CSS |
| Mapping | Leaflet and React Leaflet with OpenStreetMap tiles |
| Visualisation | Recharts and React Flow |
| Application APIs | Next.js route handlers under `src/app/api` |
| Data access | Drizzle ORM and PostgreSQL schema |
| Simulation | In-process graph analysis in `src/lib/simulation-engine.ts` |
| Validation and utilities | Zod, `clsx`, and `tailwind-merge` |

### Important data boundary

The current interactive API routes use the process-local `dataStore` in `src/lib/data-store.ts`. Tree additions and removals therefore persist only for the lifetime of the running process and are not yet written back to PostgreSQL. PostgreSQL is still required by the health check, database seed route, and Drizzle schema workflow. This is an intentional MVP boundary and should be addressed before treating the application as a multi-user production system.

## API Routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/api/health` | Verifies the PostgreSQL connection with `select 1`. |
| `GET` | `/api/trees` | Returns trees, summary statistics, and optional filters such as `zone`, `ecologicalValue`, `search`, `status`, and `limit`. |
| `POST` | `/api/trees` | Adds a tree to the in-memory demo store. |
| `DELETE` | `/api/trees?id=<id>` | Marks a tree as removed in the in-memory demo store. |
| `GET` | `/api/species` | Returns the species catalogue with optional search and classification filters. |
| `GET` | `/api/corridors` | Returns the configured wildlife corridors. |
| `GET` | `/api/simulations` | Returns the built-in simulation presets. |
| `POST` | `/api/simulations` | Runs a simulation from an `actions` array. |
| `POST` | `/api/seed` | Inserts the synthetic demo records into PostgreSQL. |

## Local Development

Requirements:

- Node.js 18 or newer
- npm
- PostgreSQL 14 or newer for the database-backed routes and seed workflow

For installation, environment setup, database initialization, and the guided demo, see [QUICKSTART.md](QUICKSTART.md).

```bash
npm install
npm run dev
```

Then open `http://localhost:3000`.

## Quality Checks

```bash
npm run lint
npm run typecheck
npm run build
```

Run these checks before deploying. `npm start` serves the most recent production build.

## Deployment

EcoWeaver can run on any host that supports a Next.js Node deployment and a reachable PostgreSQL database. Vercel is a convenient option for the web app; use a compatible external PostgreSQL provider and configure `DATABASE_URL` in the deployment environment.

See [HOSTING_GUIDE.md](HOSTING_GUIDE.md) for the deployment sequence, schema setup, health checks, security notes, and platform guidance.

## Scope and Roadmap

The current repository demonstrates the product workflow. A production platform would still need durable application persistence, authentication and authorization, migrations, rate limiting, observability, backups, real GIS ingestion, ecological model validation, and a secure strategy for any future AI provider integration.
